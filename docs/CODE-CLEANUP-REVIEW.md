# รายงานตรวจและปรับความอ่านง่ายของโค้ด

> รายงานนี้เก็บผลของรอบคอมเมนต์โค้ดเดิม ประเด็น TypeScript ของ tests และแพตช์ Next.js ได้จัดการในรอบติดตามแล้ว ดูผลล่าสุดใน [รายงานตรวจและส่งงาน](VERIFICATION-AND-PUBLISH.md)

วันที่ 23 ตุลาคม 2026 อ้างอิง worktree `courtside-public-platform` ก่อนเริ่มงานมีการแก้หลายไฟล์ค้างอยู่ จึงใช้ snapshot ณ ต้นรอบนี้เป็นฐานเปรียบเทียบ ไม่ใช้ความต่างจาก commit ล่าสุดทั้งหมดเหมารวมว่าเป็นงานรอบนี้

## ขอบเขต

- ตรวจไฟล์ที่ดูแลเอง 507 ไฟล์ใน app/components/features/lib/scripts/prisma/tests และ configuration
- ลบ 2 ไฟล์ที่ไม่มีผู้เรียก เหลือ 505 ไฟล์ที่เพิ่มคำอธิบายหัวไฟล์
- เพิ่มคอมเมนต์ฟังก์ชัน/จุดสำคัญ 206 จุด และคำอธิบาย model/enum ของ schema
- ทำ [คู่มือเตรียมสอบ](EXAM-CODE-GUIDE.md) และสารบัญโค้ด 19 หมวด
- เว้น generated client, dependencies, build output, ข้อมูลลับ และประวัติ migration

## การปรับโค้ดที่ทำงานจริง

| ส่วน | หลักฐาน/เหตุผล | วิธีตรวจ |
| --- | --- | --- |
| ลบ `components/ui/skeleton.tsx` | ไม่พบ import หรือการอ้างชื่อ component ใน source/test/script; หน้าสถานะโหลดใช้ส่วนแสดงผลอื่น | ตรวจ import graph, ค้นชื่อ/เส้นทาง และรัน build/test |
| ลบ `lib/supabase/browser.ts` | ไม่พบผู้เรียก createBrowserSupabaseClient; ฟอร์ม Auth ปัจจุบันส่ง HTTP ไป Route Handler | ตรวจ import graph, ค้นชื่อ/เส้นทาง และรัน build/test |
| รวม `authorizePlayerRosterAccess` | ฟังก์ชันเดิมเหมือนกันใน add/update/deactivate ผู้เล่น | ย้ายมา `team-access.ts` โดยรักษา body เดิม แล้วทดสอบ use case/API ทีม |
| อ่านการตรวจไฟล์ง่ายขึ้น | conditional expression ซ้อนหลายชั้นอ่านยาก และมี `as never` ที่ไม่จำเป็น | ใช้ switch แยก MIME type และ some เทียบค่าที่อนุญาต; รัน media-policy tests |

ไม่มีการเปลี่ยนกติกาทางธุรกิจ ฐานข้อมูล dependency หรือหน้าตาของระบบในรอบนี้

## ส่วนที่ตรวจแล้วและยังเก็บ

- page/layout/route/error/loading เป็นจุดเริ่มต้นที่ Next.js เรียกตามชื่อไฟล์ จึงไม่ถือเป็นไฟล์ตายเพียงเพราะไม่มี import
- mock/development adapters ยังถูกเรียกผ่าน factory หรือใช้ในเทสต์
- วิธีจัดสาย seed เดิมยังถูกใช้ในชุดสาธิต/เทสต์ ส่วนหน้า UI ปัจจุบันเรียกวิธี ORDERED/RANDOM_ORDERED
- TeamMember และเครื่องมือตรวจ legacy ยังใช้ทบทวนข้อมูลแบบเดิม; การลบตารางไม่ได้อยู่ในงานลดความซับซ้อนนี้
- version, transaction, row lock และ audit เป็นกฎป้องกันข้อมูลผิด ต้องคงไว้แม้ไม่ปรากฏเป็นปุ่มบนหน้าเว็บ
- config ของ ESLint, PostCSS, Prisma และ Vitest ถูกเรียกโดยเครื่องมือ ไม่ได้ถูก import จากหน้าเว็บ

## สิ่งที่พบก่อนปรับ

TypeScript ของ source ตาม `tsconfig.build.json` ผ่านแม้เปิด noUnusedLocals/noUnusedParameters เพิ่ม จึงไม่พบตัวแปร/import ที่ไม่ใช้งานใน source ชุดนี้

TypeScript ทั้งโครงการที่รวม tests ยังมีข้อผิดพลาดชนิดข้อมูลของ mock/fixture เดิม เช่น object ที่ขาดฟิลด์และ mock infer ชนิดไม่ครบ ตัว build แยก tests ออกอยู่แล้ว การรัน Vitest และการตรวจชนิดข้อมูลทุกไฟล์เป็นคนละขั้นตอน ประเด็นนี้บันทึกเป็นงานที่เหลือ ไม่อ้างว่าแก้ในรอบนี้

### ข้อจำกัดและงานถัดไป

- Next.js 16.4.0 ที่ติดตั้งแจ้งเตือนช่องโหว่ความปลอดภัยระหว่าง build: ครั้งแรกหยุดด้วย `SecurityFatalError` และรันซ้ำผ่านพร้อมคำเตือน จึงควรจัดการอัปเดตความปลอดภัยเป็นงานแยกพร้อม regression tests ไม่ถือว่า build ผ่านแล้วคำเตือนหายไป
- ชนิดข้อมูล mock/fixture ใน tests ที่กล่าวไว้ด้านบนยังไม่ได้แก้; ผล Vitest ผ่านไม่ได้แปลว่าการตรวจ TypeScript แบบรวม tests ผ่าน
- รอบนี้ไม่มีการเปลี่ยน UI และไม่ได้ทดสอบเว็บจริงหรือเขียนข้อมูลลงฐานข้อมูลจริงใหม่ ผลตรวจนี้เป็น automated tests, source comparison และ local production build
- คอมเมนต์ครอบคลุมหัวไฟล์ที่ดูแลเองทุกไฟล์และฟังก์ชัน/บล็อกสำคัญ ไม่ใช่การแปล syntax ทุกบรรทัด; dependencies และ generated code ไม่แก้ไข
